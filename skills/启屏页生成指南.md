# 启屏页生成指南 (Splash Generation Guide)

> 本文档定义了启屏页在 Android 原生、iOS 原生及 Compose Multiplatform 层级实现“视觉零跳变”的同步标准。AI 必须基于此规范执行自动化对齐。

## 1. 核心目标
实现“打底无缝衔接”。采用 **“极简原生启屏 (Minimal Native Splash)”** 方案：
- **原生层 (Native Layer)**：仅提供背景打底（单色或代码渐变）。由开发者在两路策略中选择实现方式。
- **Compose 层 (Compose Layer)**：负责全量视觉还原（Logo、字号、Slogan、版权等）。严格按照 UI 设计稿进行切图引用或组件拼装，不再受原生策略限制。

## 2. 视觉指纹参数 (Visual Identity Standards)
AI 执行任务时，必须通过视觉分析，动态提取并维护以下变量契约：
- **NATIVE_BG_STRATEGY**: **仅针对原生主题/Storyboard 的背景实现策略**：
    1. `NATIVE_COLOR`: **原生代码/色值方案**。由 AI 提取色值并用原生 XML/Storyboard 实现打底。
    2. `NATIVE_AI_DESIGN`: **原生仿真方案**。由 AI 自行设计接近设计稿的原生布局（如用 Layer-list 模拟渐变）。
- **COMPOSE_UI_SPEC**: 
    - `logo_asset`: 前景 Logo 资源。
    - `wordmark_asset`: 品牌字号资源（若有）。
    - `slogan_text`: 标语内容。
    - `copyright_text`: 版权内容。

## 3. 三端适配与兼容策略

### 3.1 原生打底策略 (针对 Native Layer)
AI 必须基于开发者选择的 `NATIVE_BG_STRATEGY` 执行实现：
- **方案 1 (NATIVE_COLOR)**：
    - **Android (Critical Constraint)**：在 API 31+ 下，`windowSplashScreenBackground` **仅支持单色 (Color)**。AI 必须提取设计图背景的顶部/核心色值。禁止在此属性引用 Gradient Drawable，否则会导致黑屏。
    - **iOS**：设置根 View 的背景色。
- **方案 2 (NATIVE_AI_DESIGN)**：AI 尝试通过 XML 绘制最接近的背景感官。

### 3.2 Compose 全量还原 (针对 Compose Layer)
- **视觉还原**：直接使用 `Image` 引用 UI 设计稿切图，不再使用 Canvas 仿真。
- **状态栏联动**：根据背景亮度设置 `statusBarTextIsDark`。

## 4. 自动化任务流程：同步启屏页

当收到发图或指令时，AI 执行以下操作：
1. **决策阶段 (Decision Phase)**：
    - **策略询问 (Mandatory)**：**仅针对原生打底层**，请开发者确认方案（代码/仿真）。
2. **多点注入 (Injection Phase)**：
    - **Step A**: 修改 Android `themes.xml` (根据策略实现打底)。
    - **Step B**: 物理修改 iOS Storyboard XML (根据策略实现打底)。
    - **Step C**: 重构 Compose 启屏类，按照 UI 设计稿正常引用资源（Image）进行全量拼装。
3. **自检报告**：输出 [视觉对齐核对表]。
