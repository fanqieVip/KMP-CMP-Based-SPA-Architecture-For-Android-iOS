# 通用代码规范

> 本文档定义了项目跨模块通用的编码美学、元数据标准及环境自检规约。

## 1. 文件头注释标准 (File Header)

新建任何源代码文件（Kotlin/Swift）时，**必须**包含标准的类注释头。

### 1.1 模板要求
```kotlin
/**
 * @Description: [简述类或文件的职责，须结合架构上下文]
 * @Author:         [动态获取 git config user.name]
 * @CreateDate:     [动态获取当前时间，格式：YYYY/MM/DD HH:MM]
 */
```

### 1.2 强制约束
- **Author 真实性**：优先从环境 `git config user.name` 获取。**严禁**使用 `admin`、`staff`、拼音缩写（如 `fanj`）等非真实姓名。
- **时间动态化**：`@CreateDate` 必须通过系统命令（如 `date`）实时获取，禁止硬编码或使用过时占位符。
- **标签清理**：**严禁**出现 `@Version` 标签，除非用户明确要求。
- **描述质量**：`@Description` 必须清晰描述该文件在项目中的职责，禁止留空。

## 2. 环境自检规约 (Environment Self-Check)

AI 在执行编码任务（Phase 4）前，必须进行以下环境核对：

1.  **Git 身份核对**：通过 `run_shell_command` 执行 `git config user.name`。
    - 若获取到的名称为缩写或非真实姓名，必须使用 `ask_user` 询问用户真实姓名，并引导用户更新全局 Git 配置。
2.  **动态变量注入**：所有注释字段必须在写入前实时生成，确保信息的准确性。

## 3. 命名与工程美学

- **资源对齐**：所有新增文件必须遵循 `skills/资源与切图规范.md` 中的命名与 Import 规则。
- **架构一致性**：业务页面必须遵循 `skills/UI组件使用指南及规范.md` 的 Screen/ScreenModel 结构。
