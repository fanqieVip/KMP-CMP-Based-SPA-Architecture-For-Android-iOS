# 组件实战指南

> 本文档深入探讨复杂 UI 组件的联动、嵌套滑动冲突解决及生命周期同步逻辑。

## 1. 交互状态与分页联动

### 1.1 BasicInteraction
负责页面整体状态：`loading -> success/error/empty`。
- 首次加载成功：`uiSuccess(data.isEmpty())`。
- 首次加载失败：`uiError(code, error)`。
- **多层嵌套准则**：如果多层同时开启 `BasicInteraction`，应遵循“外层负责骨架加载，内层负责数据刷新”的原则。建议内层使用 `localLoading` 或 `popLoading` 策略，避免 UI 遮挡冲突。

### 1.2 PagingControl
负责列表层面的局部状态：下拉刷新与上拉加载。
- 必须在 ScreenModel 中实现 `PagingControl` 接口。
- 加载完成调用 `pagingOver(isOver)`，框架会自动处理 Loading 消失和 Toast。

## 2. 分栏组件 (Pager) 高级用法

### 2.1 生命周期同步
- **规则**：Pager 内每个 Tab 的 `ScreenModel` **必须**在 Tab 内容 Composable 内部创建。
- **原因**：这样模型才能通过 `LocalPageLifecycleVisible` 正确感知当前 Tab 是否可见，从而触发 `onVisible` / `onInvisible`。

### 2.2 嵌套滑动协调 (Scaffold + Pager + List)
当 `BasicHazeScaffold` 嵌套 Pager 再嵌套列表时，滑动会冲突。
- **方案**：状态提升。
- 父页面定义 `canConsumeScrollUp` 状态，并传给内页。
- 内页监听自身 `refreshState.progress`，当 `progress <= 0f` 时通过回调通知父页面：`canConsumeScrollUp = true`。

## 3. CoordinatorLayout 悬停方案

### 3.1 方案选择
- **方案 A (固定高度悬停)**：设置 `minHeaderHeight` 为悬停区高度。Header 缩到该高度后固定。
- **方案 B (随内容吸顶)**：`minHeaderHeight = 0dp`。在 content 中使用 `Column` 包裹 `[吸顶组件, 列表]`。

### 3.2 标记滚动源
- 必须给列表组件加上 `Modifier.coordinatorMainScroll`。
- 头部如需响应滑动，需加 `Modifier.coordinatorDragProxy`。

## 4. 疑难杂症处理

### 4.1 处理 Bottom 遮挡
- 当 Scaffold 有 `bottom` 槽位时，`center` 内容会被遮挡。
- **解决**：在 `center` 闭包内通过 `LocalHazeScaffoldContentPadding.current` 获取边距，并应用到列表的 `contentPadding` 上。

### 4.2 WebView 资源释放
- `WebViewState` 必须放在 `ScreenModel` 中。
- **强制要求**：在 `ScreenModel.onDestroyed()` 中调用 `webviewState.destroyed()`，否则会导致严重的内存泄漏和 JSBridge 残留。
