# 资源与切图规范

> 本文档定义了项目中图片资源的切图、存放、命名及在代码中引用的强制标准。

## 1. 资源存放位置 (Mandatory)

**核心规则：图片资源必须放在当前页面所属模块的 `composeResources/drawable/` 目录下！**

| 页面所在模块 | 图片放置路径 | 命名前缀      |
| :--- | :--- |:----------|
| `project/main` | `project/main/src/commonMain/composeResources/drawable/` | `main_`   |
| `core/common` | `core/common/src/commonMain/composeResources/drawable/` | `common_` |
| `core/base` | `core/base/src/commonMain/composeResources/drawable/` | `base_`   |
| `libs/geyan` | `libs/geyan/src/commonMain/composeResources/drawable/` | `geyan_`  |

⚠️ **注意**：即使页面中引用了 `core/common` 的组件，图片也必须放在页面所在的模块。不要跨模块放图片。

⚠️ **libs 模块隔离**：`libs/*` 是 SDK/三方能力模块，原则上不允许直接访问其他模块中的资源，包括 `core/common`、`project/*` 和其他 `libs/*`。`libs/*` 内的原生 UI、SDK 授权页或 Compose 页面需要图片时，必须放在当前 `libs/<name>/src/commonMain/composeResources/drawable/`，并使用当前模块前缀命名。

## 2. 切图规范

### 2.1 尺寸与格式
- **尺寸**：只切 **drawable-xxhdpi** 尺寸（对应 Android 375ppi）。
- **格式**：**强制优先使用 WebP 格式！** 除非有极特殊需求，否则禁止使用 PNG。

### 2.2 命名规则
- 仅支持小写字母和下划线 `_`。
- 必须带模块前缀（`main_` / `common_` / `base_`）。
- 示例：`main_ic_user_avatar.webp`

### 2.3 设计切图优先级
- 设计稿或蓝湖已经提供切图的图标、勾选框、状态图、装饰图，必须下载切图并作为本地资源接入，禁止用 `Drawable`、`Canvas`、`Shape`、SVG、XML shape 或代码路径重画替代。
- 只有设计稿明确没有切图，且经过需求方确认可以平台化绘制时，才允许使用代码绘制；代码中必须保留说明来源与确认结论。
- 原生 View / SDK UI 场景同样适用本规则：可以用 `Drawable` 包装图片以适配控件状态，但 `Drawable` 内只能渲染切图资源，不能自行绘制图标形状。

## 3. 代码引用规范 (重要：解决爆红)

使用图片资源时，**必须同时添加两行 import**，缺一不可！

### 3.1 正确写法示例

假设你在 `project/main` 模块使用 `main_ic_phone.webp`：

**文件顶部 import 区：**
```kotlin
import com.basic.main.R_com_basic_main  // 1. R 类，提供 drawable 访问
import com.basic.main.main_ic_phone     // 2. 资源名，解决编译器识别问题
```

**使用处：**
```kotlin
Image(
    painter = painterResource(R_com_basic_main.drawable.main_ic_phone),
    contentDescription = null,
    modifier = Modifier.size(24.dp),
    contentScale = ContentScale.FillWidth
)
```

### 3.2 各模块对应关系

| 模块 | namespace          | R 类名                 |
| :--- |:-------------------|:---------------------|
| `project/main` | `com.basic.main`   | `R_com_basic_main`   |
| `core/common` | `com.basic.common` | `R_com_basic_common` |
| `core/base` | `com.basic.base`   | `R_com_basic_base`   |

### 3.3 原生 View / SDK UI 引用 Compose Resources

在 Android `Activity`、原生 `View`、三方 SDK 授权页配置等非 Compose 场景中引用 `composeResources` 图片时，必须复用 `core/base` 已提供的 `ComposeResourcesKtx.kt`：

```kotlin
import com.basic.base.ktx.toDrawable

val bitmap = R_com_basic_common.getUri("drawable/common_app_icon.png").toDrawable()
```

强制约束：
- `R_com_basic_xxx` 由当前模块 namespace 生成，命名规则与 Compose 中引用图片资源一致，例如 `com.basic.geyan` 对应 `R_com_basic_geyan`。
- 原生 View / SDK UI 必须通过当前资源所属模块的 `R_com_basic_xxx.getUri("drawable/xxx.webp").toDrawable()` 加载图片，例如：
```kotlin
val bitmap = R_com_basic_geyan.getUri("drawable/geyan_login_brand.webp").toDrawable()
```
- 禁止在业务模块或 SDK 模块内重复编写 `AssetManager.open`、`BitmapFactory.decodeStream`、`UIImage.imageWithContentsOfFile` 等资源解码胶水代码。
- 禁止拼接或硬编码 Compose Resources 在平台 assets 中的 URI，例如 `"file:///android_asset/composeResources/..."`。
- 原生 UI 中仍需遵守资源归属与复用规则，不得为了原生加载便利重复切图或复制资源。

## 4. 故障排除

如果引用图片时 IDE 爆红：
1. **执行生成任务**：在终端运行 `./gradlew generateComposeResClass`。
2. **检查 Import**：确认上述“两行 import”是否都已手动添加。
3. **不要盲目重试**：不要通过修改文件名或重复切图来解决爆红问题。
